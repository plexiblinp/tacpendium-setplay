## 判断と理由

- **例の条件の確かめ**（2026-11-07。手元のエンジン `engine.SuggestJSON` を配信データの `ryu` で直に呼んだ。票は無し）: KA 32・既定では 119 件で 66 > 5HP は 20 位、KA 32・重ねる技＝立ち強P では 6 件で 1 位。⇒ 重ねる技を入れた（開発者の決定）。
- **`trigger` を省略可にし、版 `v` は 1 のまま**: 必須にすると、デプロイの後もキャッシュに残った古い画面の beacon がすべて 400 で落ちる（計測が抜ける）。版を上げると集計の `v = 1` の絞り込みから新しい点が外れる。省略できる項目を足しただけで、ほかの項目の意味は変わらないため。
- **プライバシーポリシーに 1 句足した**: いまの文「条件・結果・処理時間など」に含まれるとも読めるが、手順（`docs/maintenance.md`「ux」5）に従い、計測が増えたことを書いた。IP・個人に結び付く値は増えない。
- **「これは何？」は押して開く**（開発者の決定）。マウスを合わせて開く形はスマホで使えない。
- **お試しの案内は App で結果の上に出す**（`Results` に口を足さず、`urlRejected` の案内と同じ置き方）。
- **図の崩れの守り**: 5 言語で、図の中の文字（`getBBox`）が図の枠（800×480）からはみ出さず、メーターの見出しが数字（32F・-32F）より左で終わることを E2E で見る（スマホ幅 360px）。
- beacon の大きさ: 長めの値（キャラ code 32 字・技 code 40 字・誤りの code 32 字・データ版 64 字・当てる技の種別すべて）で JSON が約 800 バイト（`node -e` で数えた）。上限 1KB に収まる。推測: 実際の値はこれより短い。
