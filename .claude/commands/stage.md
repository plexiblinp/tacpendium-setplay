段階 **S$ARGUMENTS** を最後まで進める。規約は `AGENTS.md`（とくに §2 読むもの・§3 進め方・§8 検証と報告）。

- 引数が空なら、`docs/progress/` の最新の `S<n>-report.md` の次の段階とする。報告が 1 件も無ければ S0。
- **段階は S9 で終わり**（2026-10-25 に一般公開）。S10 以降を指されたら・S9 の後に引数が空なら、段階は進めず、公開後の作業として `/maint`（`.claude/commands/maint.md`）の手順で進める。
- 承認は待たない。**AGENTS.md §3「止めて開発者に聞くもの」に当たるときだけ** AskUserQuestion で止まる（選択肢と推奨を添える）。

## 1. 読む
- AGENTS.md §2 の「全段階共通」と自段階の行に挙がったものだけを読む。全文を読むのは表に無い判断が要るときだけ。
- 段階の開始コミットを記録する: `git rev-parse HEAD`（§8 の diff の基準になる）。

## 2. 計画
- `docs/progress/S<n>-report.md` を作り、冒頭に「計画」節を書く: 完了条件（HANDOVER §9 の行）・作るファイル・回すテスト／検査・未決事項と、その扱い（自分で決める／聞く）。
- 計画の段階で決めた推測は「推測:」と書く。
- コミット・push する（以後も節目ごとに）。

## 3. 実装
- 節目ごとにコミット・push（Conventional Commits、スコープは `S<n>`）。
- テスト・検査は出力をファイルへ書き、終了コードを出す: `go test ./... > /tmp/s<n>-go.txt 2>&1; echo EXIT=$?`。合否を `| head` / `| tail` 越しに判定しない。
- 新しいテスト・検査は、守りたい不具合を一度わざと起こし、狙いどおり赤くなることを確かめる（AGENTS §8-3）。

## 4. レビュー（新しいサブエージェント）
- Agent ツールで **general-purpose のサブエージェントを新しく起動する（fork しない。レビュアーが実装の文脈を持たないことが目的）**。
- 渡すもの: 段階番号・開始コミット・`.claude/commands/review.md` を読んでその手順に従うこと・報告先 `docs/progress/S<n>-review.md`・「読み取り専用。報告ファイル以外は書かない」。
- 戻ってきたら、指摘ごとに **採用／不採用と理由** を review ファイル末尾の「取り込み」節に追記し、採用分を直す。
  - 「高」を不採用にするときだけ開発者に聞く。
- 再レビューは最大 2 往復。残った指摘は完了報告の「残課題」へ。記録して止めるのは正規の終わり方である。

## 5. 完了報告と停止
- `S<n>-report.md` に AGENTS §3「完了報告」の 4 項目を書く。§8 の証拠（`EXIT=` と件数の逐語・`git diff --stat <開始コミット>`）を必ず含める。
- 報告を書いた後に検査をもう一度回し、結果が報告と一致することを確かめる。
- コミット・push し、ローカルとリモートの SHA が一致することを確かめて停止する。**次の段階へは進まない。**
- 最後の応答には: 完了条件を満たしたか／主要な判断／残課題／開発者に決めてほしいこと（あれば）を短く書く。
